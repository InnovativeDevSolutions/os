# Project Structure

This guide explains the Forge OS codebase organization, helping you understand where to find and modify code.

## Directory Overview

```
forge_os/
├── mpmissions/
│   └── forge_os_bare.VR/          # Main mission folder
│       ├── Win99/                  # Backend (SQF)
│       ├── Win99UI/                # Frontend (JS/HTML/CSS)
│       ├── snet/                   # Media files
│       ├── tools/                  # Development utilities
│       ├── ui/                     # Legacy UI files
│       ├── init.sqf                # Mission initialization
│       ├── initServer.sqf          # Server initialization
│       ├── initPlayerLocal.sqf     # Client initialization
│       └── description.ext         # Mission configuration
├── addons/                         # Optional addon folder
├── docus/                          # Documentation (this site)
└── README.md                       # Project readme
```

│   └── XEH_*.sqf                   # Extended Event Handlers

### HashMapObject Pattern

Forge OS 2.0 uses HashMapObject instances for application state:

```sqf
// Create an application instance
private _calendar = [] call win99_calendar_fnc_createCalendar;

// Call methods
_calendar call ["createEvent", [_eventData]];
_calendar call ["getEvents", []];
```

### CBA Extended Event Handlers (XEH)

Each backend module uses CBA's Extended Event Handler system for initialization:

- **XEH_preStart.sqf** - Runs before mission starts
- **XEH_preInit.sqf** - Runs at mission init (client and server)
- **XEH_preInit_server.sqf** - Runs at mission init (server only)
- **XEH_postInit.sqf** - Runs after mission init (client and server)
- **XEH_postInit_server.sqf** - Runs after mission init (server only)
- **XEH_postInit_client.sqf** - Runs after mission init (client only)

Functions are stored in `functions/` subdirectories and use the `fnc_` prefix.

### Key Files

| File | Purpose |
|------|---------|
| `Win99/*/functions/fnc_*.sqf` | Application instance creators and utilities |
| `Win99/*/XEH_*.sqf` | Extended Event Handlers for CBA integration |
| `initPlayerLocal.sqf` | JSDialog event handler |
| `description.ext` | Mission configuration |

### Core Modules

#### config.js

Central configuration for the entire OS:

- **Start Menu**: Menu structure and program shortcuts
- **Desktop Icons**: Shortcut definitions and layout
- **Applications**: System and web app registry
- **SNet Filesystem**: Virtual file system structure

#### main.js (Win99OS)

The main OS orchestrator that:
1. Initializes base components (overlay, wallpaper, window system)
2. Loads all applications
3. Initializes UI components (taskbar, start menu, desktop)
4. Manages application lifecycle

#### loader.js (ComponentLoader)

Dynamic component loading system:
- Loads JavaScript, CSS, and HTML files
- Decompresses zlib-encoded CSS (`.css.b64`)
- Injects components into the DOM

#### a3bridge.js (A3Bridge)

Communication bridge between JavaScript and Arma 3:
- Sends commands to backend via `alert()`
- Loads files from Arma file system
- Loads icons from Arma textures
- Handles callbacks from backend

#### globalFunctions.js

Global callback handlers for backend-to-frontend communication:
- **UIHandlers**: Player info and UI updates
- **MessagingHandlers**: Chat system and player status
- **NotepadHandlers**: File operations for text editor
- **CalendarHandlers**: Event management
- **SystemHandlers**: System-level state (multiplayer mode)

All handlers are exposed to window scope for A3Bridge to call directly.

### Application Architecture

All system applications follow this pattern:

```javascript
class YourApp extends Window {
    constructor() {
        super({
            title: 'App Title',
            icon: 'FORGE_FX_Icon_CA',
            width: 800,
            height: 600
        });
        
        this.element.classList.add('yourapp-window');
        this.initializeApp();
    }
    
    initializeApp() {
        // Setup UI
        // Bind events
        // Load data
    }
}

// Register globally
window.YourApp = YourApp;
```

### File Naming

- **Original files**: `filename.ext` (e.g., `promo.jpg`)
- **Base64 files**: `filename.ext.b64` (e.g., `promo.jpg.b64`)

Original files are kept for reference; only `.b64` files are loaded by the OS.

### media_to_base64.exe

Converts media files in `snet/` to base64 format:
- Scans directory recursively
- Encodes to base64
- Creates `.b64` files
- Preserves originals

## Component Loading Order

Understanding the initialization sequence:

```
1. HTML loads (index.html)
   ├─ Loads a3bridge.js
   ├─ Loads globalFunctions.js
   ├─ Loads loader.js
   ├─ Loads config.js
   └─ Loads main.js

2. Win99OS.init()
   ├─ initializeBaseComponents()
   │  ├─ Load overlay component
   │  ├─ Load wallpaper component
   │  ├─ Load desktop component
   │  ├─ Load window component
   │  └─ Load dialog component
   │
   ├─ loadApplications()
   │  ├─ Load notepad.js
   │  ├─ Load internetexplorer.js
   │  ├─ Load messenger.js
   │  ├─ Load calendar.js
   │  └─ Load snet.js (+ helpers)
   │
   ├─ initializeUserInterface()
   │  ├─ Load taskbar component
   │  └─ Load startmenu component
   │
   └─ initializeDesktop()
      └─ Create desktop icon containers
```

## File Modification Guide

### To modify the Start Menu:
→ Edit `Win99UI/js/config.js` → `startMenu.programs`

### To add a desktop icon:
→ Edit `Win99UI/js/config.js` → `desktop.shortcuts`

### To create a new app:
→ Create `Win99UI/apps/myapp.js`
→ Register in `Win99UI/js/config.js` → `applications.system`

### To add media files:
→ Add files to `snet/[category]/`
→ Run `tools/media_to_base64.exe`
→ Register in `Win99UI/js/config.js` → `snetFilesystem`

### To modify window appearance:
→ Edit `Win99UI/components/window/window.css`

### To change desktop styling:
→ Edit `Win99UI/components/desktop/desktop.css`

## CSS File Compression

CSS files are stored in compressed format (`.css.b64`) to reduce size:

**Original**: `component.css` (uncompressed source)
**Compressed**: `component.css.b64` (zlib deflate + base64)

The `ComponentLoader` automatically decompresses `.css.b64` files when loading.

## Communication Flow

### Browser → Arma

```
JavaScript                  Arma 3
─────────                  ──────
A3Bridge.sendCommand()
    ↓
alert(JSON)
    ↓
JSDialog event   ────────→  initPlayerLocal.sqf
                            ↓
                       Event handler
                            ↓
                       Route to app instance
                            ↓
                       Execute method
```

### Arma → Browser

```
Arma 3                     JavaScript
──────                     ─────────
Execute SQF command
    ↓
ctrlWebBrowserAction
["ExecJS", "code"]   ────────→  Execute in browser
                                    ↓
                              Update UI
```
